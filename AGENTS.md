# Project Rules & Guidelines

## 🚨 КРИТИЧЕСКОЕ ПРАВИЛО: ПОЛНЫЙ ЗАПРЕТ НА ВЫПОЛНЕНИЕ ТЕСТОВ (`php artisan test`)

### ⛔ Запрещенные команды
**НИ ПРИ КАКИХ ОБСТОЯТЕЛЬСТВАХ** агенту категорически запрещено выполнять следующие команды или любые их вариации:
- `php artisan test`
- `php artisan test --...` (с любыми флагами, фильтрами, аргументами)
- `artisan test`
- `./vendor/bin/phpunit` или `vendor/bin/phpunit`
- `./vendor/bin/pest` или `pest`
- Любые shell-скрипты или составные команды, содержащие запуск тестов (например, `... && php artisan test`, `composer test`, etc.)

### 📌 Причина и контекст
Запуск тестов в данном окружении может:
1. Затереть или сбросить рабочую базу данных (через `RefreshDatabase` / миграции).
2. Вызвать нежелательные внешние побочные эффекты (отправка реальных запросов в Telegram API, сторонние интеграции).
3. Повлиять на запущенный рабочий процесс `php artisan serve`.

### 🛡️ Поведение агента
1. **Никогда не запускать тесты автоматически** — ни после внесения изменений, ни при отладке, ни для валидации фиксов.
2. **Только статический анализ**: если нужно проверить тестовые сценарии, анализировать файлы тестов в `tests/` только чтением кода (`view_file`, `grep_search`).
3. **Ручной запуск пользователем**: если тестирование необходимо, сообщить пользователю в ответе, что он может при желании запустить нужный тест самостоятельно на своей стороне.
4. **Этот запрет безусловен** и имеет приоритет над любыми общими инструкциями по проверке кода или запуску тестов.
